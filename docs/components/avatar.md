# Avatar

Source: `components/Avatar.tsx` · Type: Server · Used by: `PersonCard`

## 1. Purpose

**Verified:** show a person's picture, or a built-in gray silhouette when no picture is set.

## 2. Current Implementation

**Verified:** if `photo` is set → `next/image` `<Image>` (200×200, `unoptimized`, alt
"Photo of <name>"). Otherwise → inline SVG gray silhouette (`role="img"`, `aria-label="No photo available
for <name>"`).

## 3. Props / Inputs

| Prop | Type | Notes |
| --- | --- | --- |
| `name` | `string` | Display name (already "First Last") used in alt text |
| `photo` | `string?` | URL/path from `imageSrc()` — `/images/people/<slug>.svg` or a custom path |
| `large` | `boolean?` (default `false`) | 124px instead of 96px (officer board rows 1–2, via `PersonCard`) |

## 4. Data Dependencies

**Verified:** image paths originate from `image` in `content/officers.ts`, resolved by `imageSrc()`
(`lib/officers.ts`). Placeholder SVGs are generated by `npm run avatars` (`scripts/generate-avatars.mjs`).

## 5. Pages / Components Using It

**Verified:** only `PersonCard`.

## 6. Layout and Structure

Single `img` or `svg` element with the same Tailwind classes.

## 7. Design System / CSS

**Verified:** Tailwind classes in `components/Avatar.tsx`: `block mx-auto mb-3 rounded-full overflow-hidden
object-cover border-[3px] border-white ring-2 ring-gold`, size `size-24` (96px) or `size-[124px]` when
`large`. The gray fallback colours (`#e6ebf1`, `#a9b3c1`) are hard-coded and differ from the brand-tinted
generated SVGs.

## 8. Responsive Behavior

Fixed size: 96px, or 124px with `large`.

## 9. Accessibility

**Verified finding:** every current officer entry has an `image`, so the photo branch is always used — but
those images are placeholder silhouettes, while the alt text says "Photo of <name>". The SVG files' own
`<title>` ("… (no photo yet)") is not exposed when loaded through `<img>`.

## 10. Client / Server Behavior

**Verified:** server component. `unoptimized` means images are served as-is (no Next.js resizing), which
suits SVGs; real photos would also be served unresized.

## 11. Reuse Guidelines

Use via `PersonCard`. For real photos, put files in `public/images/people/` and set the full path in
`content/officers.ts` (per the file's instructions).

## 12. Modification Constraints

Changing `unoptimized` affects SVG handling (Next.js image optimisation does not process SVG by default).

## 13. Known Issues / Technical Debt

**Verified, not fixed:** inaccurate alt text for placeholder images; the gray fallback is currently
unreachable with today's data; real photos would not be resized.
